# bd-tools

Tools to preprocess MePRAM data for machine-learning experiments and to build
clinician-facing preprocessing reports.

## Preprocessing Workflow

The preprocessing entry point is:

```bash
./.venv/bin/python scripts/preprocess_pipeline.py \
  --input-path db_mepram_sepsis_vf.sqlite3 \
  --output-path preprocess_test.csv \
  --config-path config/preprocess_config.py \
  --drop-columns-path data/preprocess_columns_to_drop.txt \
  --run-label current_report_layout
```

This writes the full preprocessed dataset, the filtered/model-compatible
dataset, and audit logs next to `--output-path`.

For the example above, the generated local files are:

| Output | Contents |
|---|---|
| `preprocess_test.csv` | Full preprocessed table. Keeps all columns before final filtering. |
| `preprocess_test_filtered.csv` | Filtered/model-compatible table after applying `data/preprocess_columns_to_drop.txt`. |
| `preprocess_test_log_summary.csv` | One-row-per-stage audit summary with row/column counts, config version, Git commit metadata, script content hash, dirty flag, and run label. |
| `preprocess_test_log_detailed.json` | Detailed per-stage audit log with created, recoded, transformed, and dropped variables. |

The local root-level preprocessing outputs are ignored by Git because they can
contain sensitive or large data.

## Reproducible Run Naming

For repeated tests, use a dated run folder and include a short description in
the filenames. This keeps datasets, logs, report tables, and graphs together.

Recommended pattern:

```bash
RUN_DATE="$(date +%Y%m%d)"
RUN_LABEL="admin_fields_dropped_cef34"
RUN_ID="${RUN_DATE}_${RUN_LABEL}"
RUN_DIR="01-preprocessing/${RUN_ID}"

mkdir -p "${RUN_DIR}"

./.venv/bin/python scripts/preprocess_pipeline.py \
  --input-path db_mepram_sepsis_vf.sqlite3 \
  --output-path "${RUN_DIR}/${RUN_ID}_full.csv" \
  --config-path config/preprocess_config.py \
  --drop-columns-path data/preprocess_columns_to_drop.txt \
  --run-label "${RUN_LABEL}"
```

With this naming, the pipeline writes:

| Output | Contents |
|---|---|
| `${RUN_ID}_full.csv` | Full preprocessed dataset for this run. |
| `${RUN_ID}_full_filtered.csv` | Filtered dataset for this run. |
| `${RUN_ID}_full_log_summary.csv` | Stage-level audit summary. Check `git_head_commit`, `preprocess_script_commit`, `preprocess_script_blob`, `preprocess_code_dirty`, and `run_label` here. |
| `${RUN_ID}_full_log_detailed.json` | Detailed transformation log for reproducibility. |

The run label should be short but meaningful, for example:

- `baseline_notebook_match`
- `admin_fields_dropped`
- `cef34_family_grouping`
- `symptoms_missing_kept_na`

## Report Generation

The report entry point is:

```bash
./.venv/bin/python scripts/preprocess_report.py \
  --summary-log-path preprocess_test_log_summary.csv \
  --detailed-log-path preprocess_test_log_detailed.json \
  --full-dataset-path preprocess_test.csv \
  --filtered-dataset-path preprocess_test_filtered.csv \
  --sqlite-path db_mepram_sepsis_vf.sqlite3 \
  --output-dir preprocess_report
```

For a versioned run folder, use the matching run files:

```bash
./.venv/bin/python scripts/preprocess_report.py \
  --summary-log-path "${RUN_DIR}/${RUN_ID}_full_log_summary.csv" \
  --detailed-log-path "${RUN_DIR}/${RUN_ID}_full_log_detailed.json" \
  --full-dataset-path "${RUN_DIR}/${RUN_ID}_full.csv" \
  --filtered-dataset-path "${RUN_DIR}/${RUN_ID}_full_filtered.csv" \
  --sqlite-path db_mepram_sepsis_vf.sqlite3 \
  --output-dir "${RUN_DIR}/preprocess_report"
```

`scripts/preprocess_report.py` creates the report root plus two subfolders:

| Path | Contents |
|---|---|
| `preprocess_report/preprocessing_report.md` | Clinician/QA markdown report with dataset shapes, figures, target summaries, missingness, and stage audit summary. |
| `preprocess_report/graphs/` | PNG figures generated from the preprocessing outputs and logs. |
| `preprocess_report/tables/` | CSV summary tables and the clinician Excel variable dictionary. |

The checked-in `preprocess_report/raw_input_tables_diagram.md` is a companion source-table
overview. It is not regenerated by `scripts/preprocess_report.py`.

The report script also builds the clinician variable dictionary automatically:

| Output | Contents |
|---|---|
| `preprocess_report/tables/clinician_variable_dictionary.xlsx` | Excel workbook with variable name, transformation/recoding description, dropped yes/no, and notes column. |

Use `--skip-variable-dictionary` only when you want to regenerate report tables
and graphs without rebuilding the Excel workbook.

## Configuration Files

| File | Purpose |
|---|---|
| `config/preprocess_config.py` | Versioned clinical/domain configuration: recoding thresholds, organism groups, antimicrobial families, phenotype mappings. |
| `config/model_filters.yml` | Row-level cohort filters used by HPC modelling scripts. |
| `data/preprocess_columns_to_drop.txt` | Explicit column names and glob patterns removed from the filtered output. The full output keeps these columns. |
| `QUESTIONS_AND_ASSUMPTIONS.md` | Clinical assumptions and questions that need review before locking behavior. |

## Git Metadata

The preprocessing script records Git metadata automatically. You do not need to
maintain a manual pipeline version.

The summary and detailed logs include:

| Field | Meaning |
|---|---|
| `git_head_commit` | Repository `HEAD` commit at run time. |
| `preprocess_script_commit` | Last committed Git revision that touched `scripts/preprocess_pipeline.py`. |
| `preprocess_script_blob` | Git object hash of the current `scripts/preprocess_pipeline.py` file contents. This changes even for uncommitted edits. |
| `preprocess_code_dirty` | `yes` if preprocessing-relevant files had uncommitted changes when the run started. Checked files are `scripts/preprocess_pipeline.py`, `config/preprocess_config.py`, and `data/preprocess_columns_to_drop.txt`. |
| `run_label` | Short human-readable run description passed with `--run-label`. |

Check these fields in the summary log:

You can get the current Git hash before running with:

```bash
git rev-parse HEAD
git rev-parse --short HEAD
git log -1 --format=%H -- scripts/preprocess_pipeline.py
git hash-object scripts/preprocess_pipeline.py
git status --short -- scripts/preprocess_pipeline.py config/preprocess_config.py data/preprocess_columns_to_drop.txt
```

For a fully reproducible run, commit preprocessing-code changes before running.
If `preprocess_code_dirty` is `yes`, the log still records the current
`preprocess_script_blob`, but the run was made from uncommitted code/config and
should be treated as less reproducible unless those changes are archived.

For reproducibility, archive together:

- the full and filtered CSVs
- `*_log_summary.csv`
- `*_log_detailed.json`
- the generated `preprocess_report/` folder
